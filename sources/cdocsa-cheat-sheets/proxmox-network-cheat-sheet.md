Updated for **PVE 9.x** (9.0 / 9.1).\n\n---\n\n## Network Configuration File\n\n```bash\n# Main configuration file\n/etc/network/interfaces\n\n# Apply changes\nifreload -a                      # Apply without restart (recommended)\nsystemctl restart networking     # Physical interface\n    bridge-stp off               # Spanning tree off (single switch)\n    bridge-fd 0                  # No forwarding delay\n```\n\n### Bridge with DHCP\n\n```bash\nauto vmbr0\niface vmbr0 inet dhcp\n    bridge-ports eno1\n    bridge-stp off\n    bridge-fd 0\n```\n\n### Multiple Bridges\n\n```bash\n# Management network\nauto vmbr0\niface vmbr0 inet static\n    address 192.168.1.10/24\n    gateway 192.168.1.1\n    bridge-ports eno1\n    bridge-stp off\n    bridge-fd 0\n\n# Storage network (separate NIC)\nauto vmbr1\niface vmbr1 inet static\n    address 10.0.0.10/24\n    bridge-ports eno2\n    bridge-stp off\n    bridge-fd 0\n\n# VM-only network (no physical port = internal only)\nauto vmbr99\niface vmbr99 inet manual\n    bridge-ports none\n    bridge-stp off\n    bridge-fd 0\n```\n\n---\n\n## VLAN Configuration\n\n### VLAN on Physical Interface\n\n```bash\n# Physical interface\nauto eno1\niface eno1 inet manual\n\n# VLAN 100 interface\nauto eno1.100\niface eno1.100 inet manual\n    vlan-raw-device eno1\n\n# Bridge for VLAN 100\nauto vmbr100\niface vmbr100 inet static\n    address 192.168.100.10/24\n    bridge-ports eno1.100\n    bridge-stp off\n    bridge-fd 0\n```\n\n### VLAN-Aware Bridge (Recommended for Multiple VLANs)\n\n```bash\n# Physical interface\nauto eno1\niface eno1 inet manual\n\n# VLAN-aware bridge\nauto vmbr0\niface vmbr0 inet static\n    address 192.168.1.10/24\n    gateway 192.168.1.1\n    bridge-ports eno1\n    bridge-stp off\n    bridge-fd 0\n    bridge-vlan-aware yes        # Enable VLAN awareness\n    bridge-vids 2-4094           # Allow all VLANs (or specify range)\n\n# VMs can now use VLAN tags directly in their config\n# net0: virtio,bridge=vmbr0,tag=100\n```\n\n### Multiple VLANs with Management\n\n```bash\nauto vmbr0\niface vmbr0 inet manual\n    bridge-ports eno1\n    bridge-stp off\n    bridge-fd 0\n    bridge-vlan-aware yes\n    bridge-vids 10 20 30 100\n\n# Management VLAN (tagged on VLAN 10)\nauto vmbr0.10\niface vmbr0.10 inet static\n    address 192.168.10.10/24\n    gateway 192.168.10.1\n```\n\n---\n\n## Bonding (Link Aggregation)\n\n### LACP Bond (802.3ad) - Requires Switch Support\n\n```bash\n# Bond interface\nauto bond0\niface bond0 inet manual\n    bond-slaves eno1 eno2        # Member interfaces\n    bond-mode 802.3ad            # LACP\n    bond-miimon 100              # Link check every 100ms\n    bond-xmit-hash-policy layer3+4  # Load balance by IP+port\n\n# Bridge on bond\nauto vmbr0\niface vmbr0 inet static\n    address 192.168.1.10/24\n    gateway 192.168.1.1\n    bridge-ports bond0\n    bridge-stp off\n    bridge-fd 0\n```\n\n### Active-Backup Bond (No Switch Config Required)\n\n```bash\nauto bond0\niface bond0 inet manual\n    bond-slaves eno1 eno2\n    bond-mode active-backup      # Failover mode\n    bond-miimon 100\n    bond-primary eno1            # Preferred interface\n\nauto vmbr0\niface vmbr0 inet static\n    address 192.168.1.10/24\n    gateway 192.168.1.1\n    bridge-ports bond0\n    bridge-stp off\n    bridge-fd 0\n```\n\n### Balance-RR Bond (Round Robin)\n\n```bash\nauto bond0\niface bond0 inet manual\n    bond-slaves eno1 eno2\n    bond-mode balance-rr         # Round-robin (requires switch support)\n    bond-miimon 100\n\nauto vmbr0\niface vmbr0 inet static\n    address 192.168.1.10/24\n    gateway 192.168.1.1\n    bridge-ports bond0\n    bridge-stp off\n    bridge-fd 0\n```\n\n### Bond Modes Reference\n\n| Mode | Name | Switch Config | Use Case |\n|------|------|---------------|----------|\n| 0 | balance-rr | Yes | Not recommended |\n| 1 | active-backup | No | Failover, no aggregation |\n| 2 | balance-xor | Yes | Static LAG |\n| 3 | broadcast | Yes | Specialized use |\n| 4 | 802.3ad | Yes (LACP) | Best for aggregation |\n| 5 | balance-tlb | No | Outbound load balance |\n| 6 | balance-alb | No | Full load balance |\n\n---\n\n## Interface Naming & Pinning\n\n> **PVE 9 Warning:** Network interface names can change when upgrading to PVE 9 due to kernel 6.14+ recognizing new NIC features. Pin your interfaces before upgrading.\n\n### Consistent Interface Naming (Systemd)\n\n```bash\n# Modern naming scheme (eno1, enp0s3, ens192)\n# Based on: firmware/topology paths\n\n# Check current names\nip link show\nls -l /sys/class/net/\n```\n\n### Interface Pinning with pve-network-interface-pinning (PVE 9 — Recommended)\n\n```bash\n# Pin all interfaces (default prefix: nic)\npve-network-interface-pinning generate\n\n# Pin with custom prefix\npve-network-interface-pinning generate --prefix myprefix\n\n# Pin a specific interface\npve-network-interface-pinning generate --interface enp1s0\n\n# Pin with a specific target name\npve-network-interface-pinning generate --interface enp1s0 --target-name if42\n```\n\nThe tool auto-updates `/etc/network/interfaces`, firewall configs, and SDN configs. Generated `.link` files are placed in `/usr/local/lib/systemd/network`.\n\n### Alternative Interface Names (PVE 9)\n\nPVE 9 supports systemd alternative names (up to 128 bytes) in `/etc/network/interfaces` and firewall rules. If a NIC's primary name changes after a kernel upgrade, configurations continue to work if the old name is preserved as an alternative name.\n\n### Interface Pinning with systemd.link (Still Valid)\n\n```bash\n# /etc/systemd/network/10-eth0.link\n[Match]\nMACAddress=aa:bb:cc:dd:ee:f0\n\n[Link]\nName=eth0\n```\n\n### Legacy: Interface Pinning with udev Rules (Deprecated in PVE 9)\n\n```bash\n# Not recommended — use pve-network-interface-pinning instead\n# /etc/udev/rules.d/70-persistent-net.rules\n\nSUBSYSTEM==\"net\", ACTION==\"add\", ATTR{address}==\"aa:bb:cc:dd:ee:f0\", NAME=\"eth0\"\nSUBSYSTEM==\"net\", ACTION==\"add\", ATTR{address}==\"aa:bb:cc:dd:ee:f1\", NAME=\"eth1\"\n\n# Apply changes\nudevadm control --reload-rules\nudevadm trigger\n```\n\n---\n\n## Open vSwitch (OVS) -   # List VNets\npvesh get /cluster/sdn/zones     # List zones\n\n# Apply pending SDN changes\npvesh set /cluster/sdn            # Apply config\n```\n\n### SDN Fabrics (PVE 9.0)\n\nFabrics provide automated routing between cluster nodes using **OpenFabric** (IS-IS based) or **OSPF**.\n\n- Configured via: Datacenter → SDN → Fabrics\n- Auto-configure routing protocols on physical interfaces\n- Use cases: full-mesh Ceph networks, EVPN underlay\n- Services: `pve-sdn-commit` and `pve-firewall-commit` (one-shot) for applying pending config\n\n### SDN IPAM & DHCP (Tech Preview)\n\n- VLANs and IP schemes\n7. **Use bond mode 1 (active-backup)** if unsure about switch support\n8. **Pin interface names** with `pve-network-interface-pinning` (PVE 9) to prevent naming changes\n9. **Set
