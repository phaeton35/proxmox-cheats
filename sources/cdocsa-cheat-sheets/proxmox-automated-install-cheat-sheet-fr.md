Variantes ISO et matrice de versions\n\nTous les produits Proxmox partagent le **même cadre d'installation automatisée** — un système unifié de fichiers réponse TOML avec l'outil `proxmox-auto-install-assistant`. Le menu de démarrage de l'ISO affiche une entrée « Automated Installation » sélectionnée automatiquement après 10 secondes.\n\n### Produits supportés\n\n| Produit | Nom complet | Préfixe ISO | Cas d'usage |\n|---------|-------------|-------------|-------------|\n| **PVE** | Proxmox Virtual Environment | `proxmox-ve_*.iso` | Hyperviseur (VMs + LXC) |\n| **PBS** | Proxmox Backup Server | `proxmox-backup-server_*.iso` | Infrastructure de sauvegarde et restauration |\n| **PMG** | Proxmox Mail Gateway | `proxmox-mail-gateway_*.iso` | Passerelle de sécurité email |\n| **PDM** | Proxmox Datacenter Manager | `proxmox-datacenter-manager_*.iso` | Gestion multi-cluster |\n\n### Disponibilité des fonctionnalités par version ISO\n\n| Fonctionnalité | PVE | PBS | PMG | PDM |\n|----------------|-----|-----|-----|-----|\n| Installation automatisée (initiale) | 8.2-1 | 3.2-1 | 8.2-1 | 0.1-ALPHA-1 |\n| Webhook post-installation | 8.3-1 | 3.3-1 | — | — |\n| Hook premier démarrage | 8.3-1 | 3.3-1 | — | — |\n| `root-password-hashed` | 8.3-1 | 3.3-1 | — | — |\n| Option `--partition-label` | 8.3-1 | 3.3-1 | — | — |\n| Sous-options `fqdn` | 8.4-1 | 3.4-1 | — | — |\n| Option `reboot-mode` | 8.4-1 | 3.4-1 | — | — |\n| Clés kebab-case | 8.4-1 | 3.4-1 | — | — |\n| Dépréciation snake_case | 9.0-1 | 4.0-1 | — | — |\n| Nommage fixe des NIC | 9.1-1 | — | — | — |\n| Système de fichiers `btrfs` | Toutes | **Non** | **Non** | **Non** |\n\n> **Différence clé :** `btrfs` est une option de système de fichiers exclusive à PVE. Toutes les autres clés du fichier réponse sont identiques entre les produits.\n\n---\n\n## 2. Outil Assistant\n\n### Installation\n\n```bash\napt update && apt install proxmox-auto-install-assistant  # Installer l'outil assistant\napt install xorriso                                        # Dépendance requise pour la préparation ISO\n```\n\n### Sous-commandes disponibles\n\n```bash\nproxmox-auto-install-assistant --help              # Afficher toutes les sous-commandes\nproxmox-auto-install-assistant prepare-iso --help  # Options de préparation ISO\nproxmox-auto-install-assistant validate-answer --help  # Validation du fichier réponse\nproxmox-auto-install-assistant device-info --help  # Afficher les propriétés UDEV des périphériques\nproxmox-auto-install-assistant device-match --help # Tester la correspondance des filtres\nproxmox-auto-install-assistant system-info         # Afficher les infos DMI/MAC (JSON)\n```\n\n---\n\n## 3. Préparer l'ISO\n\nTrois modes `--fetch-from` mutuellement exclusifs déterminent comment l'installateur récupère le fichier réponse au démarrage.\n\n### Mode 1 : Réponse intégrée dans l'ISO\n\nLe fichier réponse est incorporé directement dans l'ISO — un média unique et autonome.\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from iso \\\n  --answer-file /chemin/vers/answer.toml            # Intégrer answer.toml directement dans l'ISO\n```\n\nAvec un script de premier démarrage :\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from iso \\\n  --answer-file /chemin/vers/answer.toml \\\n  --on-first-boot /chemin/vers/first-boot.sh        # Intégrer aussi le script first-boot (max 1 Mio)\n```\n\n### Mode 2 : Réponse sur une partition USB séparée\n\nL'installateur recherche une partition étiquetée `PROXMOX-AIS` (ou étiquette personnalisée) contenant `answer.toml`.\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from partition                         # Rechercher la partition PROXMOX-AIS au démarrage\n```\n\nAvec une étiquette de partition personnalisée :\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from partition \\\n  --partition-label MONENTREPRISE                    # Étiquette personnalisée (PVE 8.3+, PBS 3.3+)\n```\n\n### Mode 3 : Réponse récupérée via HTTP\n\nL'installateur envoie une requête POST JSON pour récupérer le fichier réponse depuis un serveur distant.\n\n```bash\n# URL intégrée dans l'ISO\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from http \\\n  --url \"https://10.0.0.100:8000/answer\"         # Récupérer la réponse depuis le point d'accès HTTP\n\n# URL + épinglage de certificat TLS\nproxmox-auto-install-assistant prepare-iso \\\n  /chemin/vers/proxmox-ve_9.1-1.iso \\\n  --fetch-from http \\\n  --url \"https://10.0.0.100/answer\" \\\n  --cert-fingerprint \"AA:BB:CC:DD:...\"           # Épingler l'empreinte SHA256 du certificat TLS\n```\n\nSources alternatives pour l'URL (pas besoin de `--url` dans l'ISO) :\n\n| Méthode | Fonctionnement |\n|---------|---------------|\n| Option DHCP `250` | URL fournie par le serveur DHCP |\n| Enregistrement DNS TXT | `proxmox-auto-installer.{domaine-de-recherche}` |\n| Option DHCP `251` | Empreinte de certificat TLS via DHCP |\n| Enregistrement DNS TXT | `proxmox-auto-installer-cert-fingerprint.{domaine-de-recherche}` |\n\n> **Remarque :** L'empreinte DHCP/DNS n'est récupérée que si la même méthode fournit l'URL.\n\n---\n\n## 4. Fichier réponse — Référence complète\n\nLes fichiers réponse utilisent le format [TOML](https://toml.io/). Utilisez des clés en **kebab-case** (snake_case déprécié depuis PVE 9.0 / PBS 4.0).\n\n### Squelette complet\n\n```toml\n[global]\nkeyboard = \"en-us\"\ncountry = \"us\"\nfqdn = \"host.example.com\"\nmailto = \"admin@example.com\"\ntimezone = \"America/New_York\"\nroot-password = \"changeme\"\n\n[network]\nsource = \"from-dhcp\"\n\n[disk-setup]\nfilesystem = \"zfs\"\nzfs.raid = \"raid1\"\ndisk-list = [\"sda\", \"sdb\"]\n\n[post-installation-webhook]     # Optionnel (PVE 8.3+, PBS 3.3+)\nurl = \"https://inventaire.local/hook\"\n\n[first-boot]                    # Optionnel (PVE 8.3+, PBS 3.3+)\nsource = \"from-iso\"\nordering = \"fully-up\"\n```\n\n### Section `[global]`\n\n| Clé | Requis | Description | Exemple |\n|-----|--------|-------------|---------|\n| `keyboard` | Oui | Disposition du clavier | `\"de\"`, `\"en-us\"`, `\"fr\"` |\n| `country` | Oui | Code pays à 2 lettres | `\"us\"`, `\"at\"`, `\"fr\"` |\n| `fqdn` | Oui | Chaîne FQDN ou sous-options | `\"node1.lab.local\"` |\n| `mailto` | Oui | Adresse email de root | `\"admin@example.com\"` |\n| `timezone` | Oui | Fuseau horaire tzdata | `\"Europe/Paris\"` |\n| `root-password` | Un des † | Mot de passe root en clair | `\"monmotdepasse\"` |\n| `root-password-hashed` | Un des † | Mot de passe pré-haché (pour `/etc/shadow`) | `\"$y$j9T$...\"` |\n| `root-ssh-keys` | Non | Tableau de clés publiques SSH | `[\"ssh-ed25519 AAAA...\"]` |\n| `reboot-on-error` | Non | Redémarrage auto en cas d'erreur (défaut : `false`) | `true` |\n| `reboot-mode` | Non | `\"reboot\"` (défaut) ou `\"power-off\"` | `\"power-off\"` |\n\n> † Exactement un seul parmi `root-password` ou `root-password-hashed` doit être défini. Les deux ou aucun = erreur de validation.\n\n#### Sous-options FQDN (PVE 8.4+, PBS 3.4+)\n\n```toml\n# Chaîne simple\nfqdn = \"monhote.example.com\"\n\n# Dynamique depuis DHCP avec domaine de secours\nfqdn.source = \"from-dhcp\"\nfqdn.domain = \"secours.example.com\"\n```\n\nAvec `from-dhcp`, le serveur DHCP **doit** fournir un nom d'hôte (option 12). Le domaine (option 15) est optionnel — `fqdn.domain` sert de valeur de secours.\n\n#### Générer un mot de passe haché\n\n```bash\napt install whois                                # Installer l'utilitaire mkpasswd\nmkpasswd --method=yescrypt \"monmotdepasse\"       # Générer un hash yescrypt pour le fichier réponse\n```\n\n#### Dispositions de clavier supportées\n\n```text\nde  de-ch  dk  en-gb  en-us  es  fi  fr  fr-be  fr-ca  fr-ch\nhu  is  it  jp  lt  mk  nl  no  pl  pt  pt-br  se  si  tr\n```\n\n### Section `[network]`\n\n| Clé | Requis | Description | Exemple |\n|-----|--------|-------------|---------|\n| `source` | Oui | `\"from-dhcp\"` ou `\"from-answer\"` | `\"from-dhcp\"` |\n| `cidr` | Si `from-answer` | Adresse IP en notation CIDR | `\"192.168.1.10/24\"` |\n| `dns` | Si `from-answer` | Adresse IP du serveur DNS | `\"192.168.1.1\"` |\n| `gateway` | Si `from-answer` | Adresse IP de la passerelle par défaut | `\"192.168.1.1\"` |\n| `filter` | Si `from-answer` | Filtre UDEV pour sélectionner la carte réseau | `filter.ID_NET_NAME_MAC = \"*aabbcc\"` |\n\n> Avec `from-dhcp`, ne définissez **pas** `cidr`, `dns`, `gateway` ni `filter`. L'installateur utilise le bail DHCP pour écrire une configuration réseau statique.\n\n#### Nommage fixe des interfaces réseau (PVE 9.1+)\n\n```toml\n[network]\nsource = \"from-dhcp\"\n\n[network.interface-name-pinning]\nenabled = true\n\n[network.interface-name-pinning.mapping]\n\"24:8a:07:1e:05:bc\" = \"lan0\"                    # Associer l'adresse MAC au nom d'interface \"lan0\"\n\"24:8a:07:1e:05:bd\" = \"lan1\"                    # Associer l'adresse MAC au nom d'interface \"lan1\"\n\"b4:2e:99:ac:ad:b4\" = \"mgmt\"                    # Associer l'adresse MAC au nom d'interface \"mgmt\"\n```\n\nSans `[mapping]`, les interfaces sont nommées automatiquement `nic0`, `nic1`, `nic2`, etc.\n\n### Section `[disk-setup]`\n\n| Clé | Requis | Description | Exemple |\n|-----|--------|-------------|---------|\n| `filesystem` | Oui | `ext4`, `xfs`, `zfs` ou `btrfs` (PVE uniquement) | `\"zfs\"` |\n| `disk-list` | Un des ‡ | Noms de disques explicites | `[\"sda\", \"sdb\"]` |\n| `filter` | Un des ‡ | Filtre UDEV pour la sélection des disques | `filter.ID_MODEL = \"Samsung*\"` |\n| `filter-match` | Non | `\"any\"` (défaut) ou `\"all\"` | `\"all\"` |\n\n> ‡ Utilisez soit `disk-list` soit `filter`, jamais les deux. Les disques dans `disk-list` qui sont inaccessibles sont ignorés silencieusement s'il en reste suffisamment.\n\n#### Options ZFS (`zfs.*`)\n\n```toml\n[disk-setup]\nfilesystem = \"zfs\"\nzfs.raid = \"raid1\"                               # raid0, raid1, raid10, raidz-1, raidz-2, raidz-3\nzfs.hdsize = 150                                 # Utiliser seulement 150 Go par disque (reste libre)\nzfs.ashift = 12                                  # Décalage de taille de secteur (12 = secteurs 4K)\nzfs.arc-max = 4096                               # Mémoire ARC maximale en Mio\nzfs.checksum = \"on\"                              # on (défaut), fletcher4, sha256\nzfs.compress = \"lz4\"                             # on, off, lzjb, lz4, zle, gzip, zstd\nzfs.copies = 1                                   # Nombre de copies de données dans le pool\n```\n\n#### Options LVM (`lvm.*`) — Pour ext4/xfs\n\n```toml\n[disk-setup]\nfilesystem = \"ext4\"\nlvm.hdsize = 200                                 # Espace disque total à utiliser en Go\nlvm.swapsize = 8                                 # Taille du volume swap en Go (défaut : RAM entre 4-8)\nlvm.maxroot = 50                                 # Taille max du volume racine en Go (défaut : hdsize/4)\nlvm.maxvz = 100                                  # Taille max du volume de données en Go\nlvm.minfree = 10                                 # Espace libre à conserver dans le VG en Go\n```\n\n#### Options BTRFS (`btrfs.*`) — PVE uniquement\n\n```toml\n[disk-setup]\nfilesystem = \"btrfs\"\nbtrfs.raid = \"raid1\"                             # raid0, raid1, raid10\nbtrfs.hdsize = 200                               # Espace disque total à utiliser en Go\nbtrfs.compress = \"zstd\"                          # on, off, zlib, lzo, zstd (défaut : off)\n```\n\n> **Attention :** `btrfs` n'est disponible que sur les ISO Proxmox VE. PBS, PMG et PDM ne le supportent pas. En mode HTTP, le serveur peut vérifier `product.enable_btrfs` dans le JSON POST.\n\n### Section `[post-installation-webhook]` (Optionnelle)\n\nDisponible depuis PVE 8.3-1, PBS 3.3-1.\n\n```toml\n[post-installation-webhook]\nurl = \"https://inventaire.local/postinst\"        # Point d'accès HTTP POST pour le rapport d'installation\ncert-fingerprint = \"AA:E8:CB:95:B1:...\"          # Épinglage TLS SHA256 optionnel\n```\n\n### Section `[first-boot]` (Optionnelle)\n\nDisponible depuis PVE 8.3-1, PBS 3.3-1. Exécute un script/binaire au premier démarrage du système après l'installation.\n\n```toml\n[first-boot]\nsource = \"from-iso\"                              # from-iso ou from-url\nordering = \"fully-up\"                            # Quand exécuter (voir ci-dessous)\n```\n\n| Valeur `ordering` | Moment d'exécution |\n|--------------------|--------------------|\n| `before-network` | Avant toute configuration réseau |\n| `network-online` | Après l'établissement de la connectivité réseau |\n| `fully-up` | Système entièrement démarré, API disponibles (défaut) |\n\nVariante depuis une URL :\n\n```toml\n[first-boot]\nsource = \"from-url\"\nordering = \"network-online\"\nurl = \"https://deploy.local/first-boot.sh\"       # Télécharger le script au premier démarrage\ncert-fingerprint = \"AA:E8:CB:95:B1:...\"          # Épinglage TLS optionnel\n```\n\n**Contraintes :**\n\n- Taille maximale du fichier : 1 Mio (pour `from-iso` et `from-url`)\n- Les scripts doivent commencer par un shebang (`#!/bin/bash`, `#!/usr/bin/env python3`, etc.)\n- Les binaires doivent être liés statiquement pour x86_64\n- Seuls les interpréteurs déjà présents après l'installation ISO peuvent être utilisés\n- Supprimer après usage : `apt purge proxmox-first-boot`\n\n---\n\n## 5. Système de filtres\n\nLes filtres correspondent aux propriétés UDEV des périphériques en utilisant des motifs de type glob.\n\n### Syntaxe des filtres\n\n| Motif | Signification | Exemple |\n|-------|---------------|---------|\n| `?` | N'importe quel caractère unique | `Samsung?SSD` |\n| `*` | N'importe quel nombre de caractères (y compris aucun) | `Samsung*` |\n| `[a-z]` | Plage de caractères | `sd[a-c]` |\n| `[abc]` | Ensemble de caractères | `sd[ab]` |\n| `[!a]` | Négation (tout caractère sauf ceux spécifiés) | `[!n]vme*` |\n\n### Propriétés utiles des disques\n\n| Propriété | Description | Exemple de valeur |\n|-----------|-------------|-------------------|\n| `DEVNAME` | Chemin du périphérique | `/dev/sda` |\n| `ID_SERIAL_SHORT` | Numéro de série court | `9DU0A02D0L33` |\n| `ID_WWN` | World Wide Name | `eui.01000000...` |\n| `ID_MODEL` | Modèle du disque | `Samsung SSD 870` |\n| `ID_SERIAL` | Chaîne de série complète | `Samsung_SSD_870_EVO_S6P...` |\n\n### Propriétés utiles des cartes réseau\n\n| Propriété | Description | Exemple de valeur |\n|-----------|-------------|-------------------|\n| `ID_NET_NAME` | Nom d'interface prédictible | `enp6s18` |\n| `ID_NET_NAME_MAC` | Nom d'interface basé sur MAC | `enxe43d1afa379a` |\n| `ID_VENDOR_FROM_DATABASE` | Fabricant de la carte réseau | `Intel Corporation` |\n| `ID_MODEL_FROM_DATABASE` | Modèle de la carte réseau | `I210 Gigabit Network` |\n\n### Exemples de filtres dans les fichiers réponse\n\n```toml\n# Disque : correspondre à tous les disques Samsung\nfilter.ID_MODEL = \"Samsung*\"\n\n# Disque : correspondre à un numéro de série spécifique\nfilter.ID_SERIAL_SHORT = \"9DU0A02D0L33\"\n\n# Disque : correspondre à plusieurs modèles (filter-match = \"any\")\nfilter.ID_SERIAL = \"KIOXIA*\"\nfilter.ID_MODEL = \"ATP*\"\nfilter-match = \"any\"                             # Correspondre si N'IMPORTE QUEL filtre est validé (défaut)\n\n# Carte réseau : correspondre par MAC (noter le * — ID_NET_NAME_MAC a le préfixe \"enx\")\nfilter.ID_NET_NAME_MAC = \"*e43d1afa379a\"\n```\n\n---\n\n## 6. Dépannage\n\nSi l'installation automatisée échoue, elle bascule vers un shell de récupération (sauf si `reboot-on-error = true`).\n\n### Fichiers journaux\n\n```bash\ncat /tmp/fetch_answer.log                        # Étapes de récupération du fichier réponse\ncat /tmp/auto_installer                          # Analyse de la réponse + correspondance matérielle\ncat /tmp/install-low-level-start-session.log     # Processus d'installation réel\n```\n\n### Problèmes courants\n\n| Problème | Cause | Solution |\n|----------|-------|----------|\n| « No answer file found » | Mauvais mode `--fetch-from` ou étiquette de partition manquante | Vérifier que l'ISO a été préparé avec le bon mode ; vérifier que l'étiquette USB est `PROXMOX-AIS` |\n| « Need either disk-list or filter set » | Sélection de disque manquante dans `[disk-setup]` | Ajouter `disk-list` ou `filter` (pas les deux) |\n| « Neither root-password nor root-password-hashed set » | Pas de mot de passe dans `[global]` | Ajouter exactement une des deux clés de mot de passe |\n| « Both root-password and root-password-hashed set » | Les deux méthodes de mot de passe présentes | En supprimer une — utiliser uniquement `root-password` ou `root-password-hashed` |\n| Timeout réseau (mode HTTP) | Serveur injoignable ou pas d'URL fournie | Vérifier l'option DHCP 250, l'enregistrement DNS TXT ou `--url` dans l'ISO |\n| « btrfs not supported » | Utilisation de `btrfs` sur une ISO PBS/PMG/PDM | Seul PVE supporte `btrfs` ; passer à `ext4`, `xfs` ou `zfs` |\n| Erreur FQDN avec `from-dhcp` | Le DHCP ne fournit pas le nom d'hôte (option 12) | S'assurer que le serveur DHCP envoie le nom d'hôte, ou utiliser une chaîne `fqdn` simple |\n| Le filtre ne correspond à aucun périphérique | Propriété UDEV ou motif glob incorrect | Utiliser `device-info` et `device-match` pour tester les filtres avant le déploiement |\n| Avertissement de dépréciation snake_case | Clés en ancien format sur PVE 9.0+ / PBS 4.0+ | Migrer vers le kebab-case (ex. `root_password` → `root-password`) |\n\n### Processus de débogage rapide\n\n```bash\n# 1. Glossaire\n\n| Terme | Définition |\n|-------|-----------|\n| **Fichier réponse (Answer File)** | Fichier de configuration au format TOML qui fournit tous les paramètres pour une installation Proxmox sans surveillance (mot de passe root, réseau, configuration disque) |\n| **TOML** | Tom's Obvious, Minimal Language — format de fichier de configuration utilisé pour les fichiers réponse Proxmox (voir [toml.io](https://toml.io/)) |\n| **UDEV** | Sous-système Linux pour les événements et propriétés des périphériques ; utilisé par les filtres Proxmox pour faire correspondre les disques et cartes réseau par numéro de série, modèle, MAC, etc. |\n| **FQDN** | Nom de Domaine Pleinement Qualifié — nom d'hôte complet incluant le domaine (ex. `node1.cluster.local`) |\n| **PVE** | Proxmox Virtual Environment — plateforme hyperviseur open source pour les VMs et conteneurs LXC |\n| **PBS** | Proxmox Backup Server — solution dédiée de sauvegarde et restauration avec déduplication, chiffrement et vérification d'intégrité |\n| **PMG** | Proxmox Mail Gateway — appliance de sécurité email avec anti-spam, anti-virus et gestion de politiques |\n| **PDM** | Proxmox Datacenter Manager — gestion centralisée de multiples clusters Proxmox VE (introduit en version 0.1-ALPHA) |\n| **Hook premier démarrage (First-Boot Hook)** | Script ou binaire exécuté une seule fois après le premier démarrage d'un système Proxmox fraîchement installé ; configuré via la section `[first-boot]` |\n| **Webhook** | Rappel HTTP POST envoyé après une installation réussie contenant l'identification complète du système (DMI, disques, cartes réseau, clés SSH) |\n| **Nommage fixe NIC (NIC Pinning)** | Fonctionnalité (PVE 9.1+) pour attribuer des noms d'interface persistants aux cartes réseau basés sur l'adresse MAC, empêchant les changements de noms entre les redémarrages |\n| **ZFS** | Zettabyte File System — système de fichiers et gestionnaire de volumes avancé avec RAID intégré, snapshots, compression et sommes de contrôle |\n| **LVM** | Logical Volume Manager — couche de gestion de disques flexible utilisée avec ext4/xfs ; permet le redimensionnement des volumes sans interruption |\n| **ARC** | Adaptive Replacement Cache — cache de lecture en mémoire de ZFS ; `zfs.arc-max` limite sa consommation mémoire |\n| **DMI** | Desktop Management Interface — données BIOS/firmware (numéros de série, UUID, informations fabricant) utilisées pour identifier le matériel physique |\n\n---\n\n## 13.
