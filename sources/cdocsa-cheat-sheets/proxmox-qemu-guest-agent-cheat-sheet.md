Enabling the Agent\n\n```bash\n# GUI: Proxmox Web UI → VM → Options → QEMU Guest Agent → Enable ✓\n\n# CLI: enable the agent\nqm set <VMID> --agent 1                          # Enable guest agent for VM\n\n# CLI: enable agent + auto-trim after clone\nqm set <VMID> --agent 1,fstrim_cloned_disks=1    # Enable agent with fstrim on clone\n\n# CLI: disable the agent\nqm set <VMID> --agent 0                          # Disable guest agent for VM\n```\n\n> **Important:** After enabling the agent on the host, you must install the guest agent inside the VM and reboot/restart the VM for communication to begin.\n\n### Communication and Diagnostics\n\n```bash\nqm agent <VMID> ping                             # Test agent connectivity\nqm agent <VMID> get-osinfo                       # Get guest OS information\nqm agent <VMID> get-host-name                    # Get guest hostname\nqm agent <VMID> get-time                         # Get guest system time\nqm agent <VMID> get-timezone                     # Get guest timezone\nqm agent <VMID> get-users                        # List logged-in users\nqm agent <VMID> get-memory-blocks                # Get memory block info\nqm agent <VMID> get-memory-block-info            # Get memory block details\n```\n\n### Network Information\n\n```bash\nqm agent <VMID> network-get-interfaces           # Get all guest network interfaces\n```\n\n### Filesystem Operations\n\n```bash\nqm agent <VMID> fsfreeze-freeze                  # Freeze guest filesystems (for snapshots)\nqm agent <VMID> fsfreeze-thaw                    # Thaw guest filesystems (after snapshots)\nqm agent <VMID> fsfreeze-status                  # Check freeze status\nqm agent <VMID> fstrim                           # Trim unused filesystem blocks\nqm agent <VMID> get-fsinfo                       # Get filesystem information\n```\n\n### File Operations\n\n```bash\nqm agent <VMID> file-read <path>                 # Read file content from guest\nqm agent <VMID> file-write <path>                # Write file content to guest\n```\n\n### Command Execution\n\n```bash\nqm agent <VMID> exec <command>                   # Execute command inside guest\nqm agent <VMID> exec-status <PID>                # Check execution status\n```\n\n### Socket Path\n\n```bash\n# Direct socket communication (advanced):\n# /var/run/qemu-server/<VMID>.qga\n```\n\n---\n\n## Debian / (Unsupported)\n\nThere is **no official QEMU Guest Agent for macOS**.\n\n### Workaround\n\n```bash\n# macOS guests on Proxmox (hackintosh-style):\n\n# Option 1: Compile from source (requires Xcode CLI tools + Homebrew)\nbrew install qemu                                 # May include qemu-ga binary\n\n# Option 2: Run without the guest agent\nqm set <VMID> --agent 0                          # Use ACPI for shutdown instead\n```\n\n### Limitations Without Guest Agent\n\n- No filesystem freeze/thaw for consistent snapshots\n- No IP address reporting in Proxmox UI\n- Graceful shutdown works via ACPI only\n- No guest command execution from host\n\n### Notes\n\n- macOS is not officially supported as a Proxmox guest\n- Running macOS on non-Apple hardware violates Apple's EULA\n- Most basic operations (start, stop, snapshots) still work without the agent\n\n---\n\n## VMware Tools vs QEMU Guest Agent\n\n| Feature | VMware Tools (open-vm-tools) | QEMU Guest Agent |\n|------|------------|\n| **qemu-guest-agent** | Daemon running inside a VM guest that communicates with the Proxmox/QEMU host via virtio-serial |\n| **virtio-serial** | Paravirtualized serial port device used as the communication channel between host and guest agent |\n| **virtio-win** | Collection of VirtIO paravirtual drivers and the QEMU Guest Agent packaged as an ISO for Windows guests |\n| **VirtIO** | Standardized paravirtual I/O framework for KVM/QEMU virtual machines (network, storage, memory, serial) |\n| **fsfreeze** | Guest agent command that freezes/thaws guest filesystems to ensure consistent snapshots |\n| **SPICE agent** | Separate agent (not qemu-ga) providing clipboard sharing, screen resize, and USB redirection for SPICE displays |\n| **Paravirtual** | Virtualization technique where the guest OS is aware of the hypervisor, enabling optimized device drivers |\n| **Balloon driver** | VirtIO driver (`virtio-balloon`) allowing the host to dynamically reclaim or allocate memory from/to a VM |\n| **`qm agent`** | Proxmox VE CLI command to interact with the QEMU Guest Agent from the host side |\n| **virtiofs** | Shared filesystem protocol for KVM/QEMU VMs, the Proxmox/KVM alternative to VMware shared folders |\n| **vioserial** | Windows VirtIO serial port driver enabling communication between the guest agent and Proxmox host |\n| **fstrim** | Discard unused
