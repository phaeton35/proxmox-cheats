Prepare ISO\n\nThree mutually exclusive `--fetch-from` modes determine how the installer retrieves the answer file at boot.\n\n### Mode 1: Answer Embedded in ISO\n\nThe answer file is baked directly into the ISO — a single self-contained medium.\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from iso \\\n  --answer-file /path/to/answer.toml            # Embed answer.toml directly in ISO\n```\n\nWith a first-boot hook script:\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from iso \\\n  --answer-file /path/to/answer.toml \\\n  --on-first-boot /path/to/first-boot.sh        # Also embed first-boot script (max 1 MiB)\n```\n\n### Mode 2: Answer on Separate USB Partition\n\nThe installer searches for a partition labeled `PROXMOX-AIS` (or custom label) containing `answer.toml`.\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from partition                         # Search for PROXMOX-AIS partition at boot\n```\n\nWith a custom partition label:\n\n```bash\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from partition \\\n  --partition-label MYCOMPANY                    # Custom label (PVE 8.3+, PBS 3.3+)\n```\n\n### Mode 3: Answer Fetched via HTTP\n\nThe installer sends a JSON POST request to retrieve the answer file from a remote server.\n\n```bash\n# URL embedded in ISO\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from http \\\n  --url \"https://10.0.0.100:8000/answer\"         # Fetch answer from HTTP endpoint\n\n# URL + TLS certificate pinning\nproxmox-auto-install-assistant prepare-iso \\\n  /path/to/proxmox-ve_9.1-1.iso \\\n  --fetch-from http \\\n  --url \"https://10.0.0.100/answer\" \\\n  --cert-fingerprint \"AA:BB:CC:DD:...\"           # Pin SHA256 TLS certificate fingerprint\n```\n\nAlternative URL sources (no `--url` needed in ISO):\n\n| Method | How It Works |\n|--------|-------------|\n| DHCP option `250` | URL provided by DHCP server |\n| DNS TXT record | `proxmox-auto-installer.{search-domain}` |\n| DHCP option `251` | TLS cert fingerprint from DHCP |\n| DNS TXT record | `proxmox-auto-installer-cert-fingerprint.{search-domain}` |\n\n> **Note:** DHCP/DNS fingerprint only fetched when same method provides URL.\n\n---\n\n## 4. Answer File — Full Reference\n\nAnswer files use [TOML](https://toml.io/) format. Use **kebab-case** keys (snake_case deprecated since PVE 9.0 / PBS 4.0).\n\n### Complete Skeleton\n\n```toml\n[global]\nkeyboard = \"en-us\"\ncountry = \"us\"\nfqdn = \"host.example.com\"\nmailto = \"admin@example.com\"\ntimezone = \"America/New_York\"\nroot-password = \"changeme\"\n\n[network]\nsource = \"from-dhcp\"\n\n[disk-setup]\nfilesystem = \"zfs\"\nzfs.raid = \"raid1\"\ndisk-list = [\"sda\", \"sdb\"]\n\n[post-installation-webhook]     # Optional (PVE 8.3+, PBS 3.3+)\nurl = \"https://inventory.local/hook\"\n\n[first-boot]                    # Optional (PVE 8.3+, PBS 3.3+)\nsource = \"from-iso\"\nordering = \"fully-up\"\n```\n\n### `[global]` Section\n\n| Key | Required | Description | Example |\n|-----|----------|-------------|---------|\n| `keyboard` | Yes | Keyboard layout | `\"de\"`, `\"en-us\"`, `\"fr\"` |\n| `country` | Yes | 2-letter country code | `\"us\"`, `\"at\"`, `\"fr\"` |\n| `fqdn` | Yes | FQDN string or sub-options | `\"node1.lab.local\"` |\n| `mailto` | Yes | Root email address | `\"admin@example.com\"` |\n| `timezone` | Yes | tzdata timezone | `\"Europe/Vienna\"` |\n| `root-password` | One of † | Plain text root password | `\"mysecretpass\"` |\n| `root-password-hashed` | One of † | Pre-hashed password (for `/etc/shadow`) | `\"$y$j9T$...\"` |\n| `root-ssh-keys` | No | SSH public keys array | `[\"ssh-ed25519 AAAA...\"]` |\n| `reboot-on-error` | No | Auto-reboot on failure (default: `false`) | `true` |\n| `reboot-mode` | No | `\"reboot\"` (default) or `\"power-off\"` | `\"power-off\"` |\n\n> † Exactly one of `root-password` or `root-password-hashed` must be set. Both or neither = validation error.\n\n#### FQDN Sub-Options (PVE 8.4+, PBS 3.4+)\n\n```toml\n# Simple string\nfqdn = \"myhost.example.com\"\n\n# Dynamic from DHCP with fallback domain\nfqdn.source = \"from-dhcp\"\nfqdn.domain = \"fallback.example.com\"\n```\n\nWhen using `from-dhcp`, the DHCP server **must** provide a hostname (option 12). The domain (option 15) is optional — `fqdn.domain` serves as fallback.\n\n#### Generate a Hashed Password\n\n```bash\napt install whois                                # Install mkpasswd utility\nmkpasswd --method=yescrypt \"mypassword\"          # Generate yescrypt hash for answer file\n```\n\n#### Supported Keyboard Layouts\n\n```text\nde  de-ch  dk  en-gb  en-us  es  fi  fr  fr-be  fr-ca  fr-ch\nhu  is  it  jp  lt  mk  nl  no  pl  pt  pt-br  se  si  tr\n```\n\n### `[network]` Section\n\n| Key | Required | Description | Example |\n|-----|----------|-------------|---------|\n| `source` | Yes | `\"from-dhcp\"` or `\"from-answer\"` | `\"from-dhcp\"` |\n| `cidr` | If `from-answer` | IP in CIDR notation | `\"192.168.1.10/24\"` |\n| `dns` | If `from-answer` | DNS server IP | `\"192.168.1.1\"` |\n| `gateway` | If `from-answer` | Default gateway IP | `\"192.168.1.1\"` |\n| `filter` | If `from-answer` | UDEV filter to select NIC | `filter.ID_NET_NAME_MAC = \"*aabbcc\"` |\n\n> With `from-dhcp`, do **not** set `cidr`, `dns`, `gateway`, or `filter`. The installer uses the DHCP lease to write a static config.\n\n#### Network Interface Name Pinning (PVE 9.1+)\n\n```toml\n[network]\nsource = \"from-dhcp\"\n\n[network.interface-name-pinning]\nenabled = true\n\n[network.interface-name-pinning.mapping]\n\"24:8a:07:1e:05:bc\" = \"lan0\"                    # Pin MAC to interface name \"lan0\"\n\"24:8a:07:1e:05:bd\" = \"lan1\"                    # Pin MAC to interface name \"lan1\"\n\"b4:2e:99:ac:ad:b4\" = \"mgmt\"                    # Pin MAC to interface name \"mgmt\"\n```\n\nWithout `[mapping]`, interfaces are auto-named `nic0`, `nic1`, `nic2`, etc.\n\n### `[disk-setup]` Section\n\n| Key | Required | Description | Example |\n|-----|----------|-------------|---------|\n| `filesystem` | Yes | `ext4`, `xfs`, `zfs`, or `btrfs` (PVE only) | `\"zfs\"` |\n| `disk-list` | One of ‡ | Explicit disk names | `[\"sda\", \"sdb\"]` |\n| `filter` | One of ‡ | UDEV filter for disk selection | `filter.ID_MODEL = \"Samsung*\"` |\n| `filter-match` | No | `\"any\"` (default) or `\"all\"` | `\"all\"` |\n\n> ‡ Use either `disk-list` or `filter`, never both. Disks in `disk-list` that are inaccessible are silently skipped if enough remain.\n\n#### ZFS Options (`zfs.*`)\n\n```toml\n[disk-setup]\nfilesystem = \"zfs\"\nzfs.raid = \"raid1\"                               # raid0, raid1, raid10, raidz-1, raidz-2, raidz-3\nzfs.hdsize = 150                                 # Use only 150 GB per disk (rest left free)\nzfs.ashift = 12                                  # Sector size shift (12 = 4K sectors)\nzfs.arc-max = 4096                               # Max ARC memory in MiB\nzfs.checksum = \"on\"                              # on (default), fletcher4, sha256\nzfs.compress = \"lz4\"                             # on, off, lzjb, lz4, zle, gzip, zstd\nzfs.copies = 1                                   # Number of data copies in pool\n```\n\n#### LVM Options (`lvm.*`) — For ext4/xfs\n\n```toml\n[disk-setup]\nfilesystem = \"ext4\"\nlvm.hdsize = 200                                 # Total disk space to use in GB\nlvm.swapsize = 8                                 # Swap volume size in GB (default: RAM capped 4-8)\nlvm.maxroot = 50                                 # Max root volume in GB (default: hdsize/4)\nlvm.maxvz = 100                                  # Max data volume in GB\nlvm.minfree = 10                                 # Free space to leave in VG in GB\n```\n\n#### BTRFS Options (`btrfs.*`) — PVE Only\n\n```toml\n[disk-setup]\nfilesystem = \"btrfs\"\nbtrfs.raid = \"raid1\"                             # raid0, raid1, raid10\nbtrfs.hdsize = 200                               # Total disk space to use in GB\nbtrfs.compress = \"zstd\"                          # on, off, zlib, lzo, zstd (default: off)\n```\n\n> **Warning:** `btrfs` is only available on Proxmox VE ISOs. PBS, PMG, and PDM do not support it. When using HTTP mode, the server can check `product.enable_btrfs` in the POST JSON.\n\n### `[post-installation-webhook]` Section (Optional)\n\nAvailable since PVE 8.3-1, PBS 3.3-1.\n\n```toml\n[post-installation-webhook]\nurl = \"https://inventory.local/postinst\"         # HTTP POST endpoint for install report\ncert-fingerprint = \"AA:E8:CB:95:B1:...\"          # Optional SHA256 TLS pin\n```\n\n### `[first-boot]` Section (Optional)\n\nAvailable since PVE 8.3-1, PBS 3.3-1. Runs a script/binary on first system boot after installation.\n\n```toml\n[first-boot]\nsource = \"from-iso\"                              # from-iso or from-url\nordering = \"fully-up\"                            # When to run (see below)\n```\n\n| `ordering` Value | When It Runs |\n|------------------|-------------|\n| `before-network` | Before any networking is set up |\n| `network-online` | After network connectivity established |\n| `fully-up` | System fully booted, APIs available (default) |\n\nFrom URL variant:\n\n```toml\n[first-boot]\nsource = \"from-url\"\nordering = \"network-online\"\nurl = \"https://deploy.local/first-boot.sh\"       # Download script at first boot\ncert-fingerprint = \"AA:E8:CB:95:B1:...\"          # Optional TLS pin\n```\n\n**Constraints:**\n\n- Max file size: 1 MiB (both `from-iso` and `from-url`)\n- Scripts must start with a shebang (`#!/bin/bash`, `#!/usr/bin/env python3`, etc.)\n- Binaries must be statically linked x86_64\n- Only interpreters already present after ISO install can be used\n- Remove after use: `apt purge proxmox-first-boot`\n\n---\n\n## 5. Filter System\n\nFilters match against UDEV device properties using glob-style patterns.\n\n### Filter Syntax\n\n| Pattern | Meaning | Example |\n|---------|---------|---------|\n| `?` | Any single character | `Samsung?SSD` |\n| `*` | Any number of characters (including none) | `Samsung*` |\n| `[a-z]` | Character range | `sd[a-c]` |\n| `[abc]` | Character set | `sd[ab]` |\n| `[!a]` | Negation (any char except specified) | `[!n]vme*` |\n\n### Useful Disk Properties\n\n| Property | Description | Example Value |\n|----------|-------------|---------------|\n| `DEVNAME` | Device path | `/dev/sda` |\n| `ID_SERIAL_SHORT` | Short serial number | `9DU0A02D0L33` |\n| `ID_WWN` | World Wide Name | `eui.01000000...` |\n| `ID_MODEL` | Disk model | `Samsung SSD 870` |\n| `ID_SERIAL` | Full serial string | `Samsung_SSD_870_EVO_S6P...` |\n\n### Useful NIC Properties\n\n| Property | Description | Example Value |\n|----------|-------------|---------------|\n| `ID_NET_NAME` | Predictable interface name | `enp6s18` |\n| `ID_NET_NAME_MAC` | MAC-based interface name | `enxe43d1afa379a` |\n| `ID_VENDOR_FROM_DATABASE` | NIC vendor | `Intel Corporation` |\n| `ID_MODEL_FROM_DATABASE` | NIC model | `I210 Gigabit Network` |\n\n### Filter Examples in Answer Files\n\n```toml\n# Disk: match all Samsung disks\nfilter.ID_MODEL = \"Samsung*\"\n\n# Disk: match specific serial\nfilter.ID_SERIAL_SHORT = \"9DU0A02D0L33\"\n\n# Disk: match multiple models (filter-match = \"any\")\nfilter.ID_SERIAL = \"KIOXIA*\"\nfilter.ID_MODEL = \"ATP*\"\nfilter-match = \"any\"                             # Match if ANY filter hits (default)\n\n# NIC: match by MAC (note the * prefix — ID_NET_NAME_MAC has \"enx\" prefix)\nfilter.ID_NET_NAME_MAC = \"*e43d1afa379a\"\n```\n\n---\n\n## 6. HTTP Answer Server\n\nWhen using `--fetch-from http`, the installer sends a JSON POST request containing system identification data (DMI, MAC addresses, disk info). The server returns an `answer.toml`.\n\n### Directory Setup\n\n```bash\nmkdir -p /srv/proxmox/auto-install-server        # Create server directory\nchmod 700 /srv/proxmox/auto-install-server        # Restrict access\n```\n\n### Option A: Static Answer via netcat (Quick & Dirty)\n\n```bash\napt install netcat-traditional                    # Install netcat\n\ncd /srv/proxmox/auto-install-server\n# Place answer.toml in this directory, then:\nwhile true; do \\\n  cat <(printf \"HTTP/1.1 200 OK\\n\\n\") answer.toml \\\n  | nc -l -q 0 -p 8000; \\\ndone &                                            # Troubleshooting\n\nIf the automated installation fails, it drops to a recovery shell (unless `reboot-on-error = true`).\n\n### Log Files\n\n```bash\ncat /tmp/fetch_answer.log                        # Answer file retrieval steps\ncat /tmp/auto_installer                          # Answer parsing + hardware matching\ncat /tmp/install-low-level-start-session.log     # Actual installation process\n```\n\n### Common Issues\n\n| Problem | Cause | Fix |\n|---------|-------|-----|\n| \"No answer file found\" | Wrong `--fetch-from` mode or missing partition label | Verify ISO was prepared with correct mode; check USB label is `PROXMOX-AIS` |\n| \"Need either disk-list or filter set\" | Missing disk selection in `[disk-setup]` | Add `disk-list` or `filter` (not both) |\n| \"Neither root-password nor root-password-hashed set\" | No password in `[global]` | Add exactly one of the two password keys |\n| \"Both root-password and root-password-hashed set\" | Both password methods present | Remove one — use only `root-password` or `root-password-hashed` |\n| Network timeout (HTTP mode) | Server unreachable or no URL provided | Check DHCP option 250, DNS TXT record, or `--url` in ISO |\n| \"btrfs not supported\" | Using `btrfs` on PBS/PMG/PDM ISO | Only PVE supports `btrfs`; switch to `ext4`, `xfs`, or `zfs` |\n| FQDN error with `from-dhcp` | DHCP not providing hostname (option 12) | Ensure DHCP server sends hostname, or use a plain `fqdn` string |\n| Filter matches no devices | Incorrect UDEV property or glob | Use `device-info` and `device-match` to test filters before deploying |\n| snake_case deprecation warning | Old-style keys on PVE 9.0+ / PBS 4.0+ | Migrate to kebab-case (e.g., `root_password` → `root-password`) |\n\n### Quick Debug Workflow\n\n```bash\n# 1. Glossary\n\n| Term | Definition |\n|------|-----------|\n| **Answer File** | TOML-formatted configuration file that provides all parameters for unattended Proxmox installation (root password, network, disk setup) |\n| **TOML** | Tom's Obvious, Minimal Language — the configuration file format used for Proxmox answer files (see [toml.io](https://toml.io/)) |\n| **UDEV** | Linux subsystem for device events and properties; used by Proxmox filters to match disks and NICs by serial, model, MAC, etc. |\n| **FQDN** | Fully Qualified Domain Name — complete hostname including domain (e.g., `node1.cluster.local`) |\n| **PVE** | Proxmox Virtual Environment — open-source hypervisor platform for VMs and LXC containers |\n| **PBS** | Proxmox Backup Server — dedicated backup and restore solution with deduplication, encryption, and integrity verification |\n| **PMG** | Proxmox Mail Gateway — email security appliance with anti-spam, anti-virus, and policy management |\n| **PDM** | Proxmox Datacenter Manager — centralized management for multiple Proxmox VE clusters (introduced as 0.1-ALPHA) |\n| **First-Boot Hook** | Script or binary executed once after the first boot of a freshly installed Proxmox system; configured via `[first-boot]` section |\n| **Webhook** | HTTP POST callback sent after successful installation containing full system identification (DMI, disks, NICs, SSH keys) |\n| **NIC Pinning** | Feature (PVE 9.1+) to assign persistent interface names to NICs based on MAC address, preventing name changes across reboots |\n| **ZFS** | Zettabyte File System — advanced filesystem and volume manager with built-in RAID, snapshots, compression, and checksumming |\n| **LVM** | Logical Volume Manager — flexible disk management layer used with ext4/xfs; allows resizing volumes without downtime |\n| **ARC** | Adaptive Replacement Cache — ZFS's in-memory read cache; `zfs.arc-max` limits its memory consumption |\n| **DMI** | Desktop Management Interface — BIOS/firmware data (serial numbers, UUID, vendor info) used to identify physical hardware |\n\n---\n\n## 13.
